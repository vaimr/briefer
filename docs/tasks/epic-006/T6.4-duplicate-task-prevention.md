# T6.4 — Duplicate Task Prevention

## Описание

Реализовать механизм предотвращения дублирования задач в Redis-очереди. Каждая задача имеет уникальный `task_id` (UUID). Если задача с таким ID уже обрабатывается или в очереди — пропустить.

## Spec

| Input | Обработка | Output |
|-------|-----------|--------|
| `task_id` (UUID) | Проверка SET `task_ids_seen` → если нет → добавить | Задача добавлена или пропущена |

## Критерии приёмки
- [ ] `bot/dedup.py` — функция `dedup_task(task_id, task_data)` → bool
- [ ] `task_id` валидируется как UUID
- [ ] Redis SET `task_ids_seen` для отслеживания
- [ ] TTL 24 часа на SET
- [ ] Возвращает True если задача новая, False если дубликат

## Граничные случаи
- `task_id` пустой → ValueError
- `task_id` не UUID → ValueError
- Redis недоступен → ConnectionError
- SET переполнен → TTL очищает старые
